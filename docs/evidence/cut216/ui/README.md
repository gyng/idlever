## Routine versus frozen package identity

Routine `armour-sets` runs without `IDLEVER_SET_INPUTS` read the real local
`web/src/engine/pkg/idlever_wasm_bg.wasm` bytes at startup. They freeze its size
and SHA, require a real package directory, and compare both the actual browser
response and final served binary against that exact current package. A shipping
build may therefore use different compiled bytes; it must still deliver its own
actual package and pass every unchanged gameplay, schema and source assertion.
This is package selection, not a claim that release-mode byte differences were
separately exercised here.

Explicit `IDLEVER_SET_INPUTS` acceptance runs remain strictly pinned to their
manifest's frozen size/SHA. Result files record `wasmScope.mode`, the fixture
manifest's historical engine, current local engine and expected engine. Mid-run
binary replacement or stale browser delivery still fails. Optional diagnostic
`IDLEVER_SET_CASES` reports the actual selected cases; the default remains the
complete six-case matrix. No frozen evidence is changed.
