# Conditional next-stage checks, prepared while outcomes are sealed

No running-study code, parameters or data were changed for this note. It is
implementation preparation only, not evidence of statistical acceptance.

`dayplayer.rs::bin_key` hashes only the file prefix before `\nfn main() {` when
IDLEVER_SRC_KEY is supplied (otherwise it hashes the executable). A future
canonical policy default must be a constant in that hashed prefix and actually
used by the default selector. Merely configuring a different mode inside main
would not invalidate the source-key cache. Keep checkpoint/profile identities
and exact-runtime safeguards intact; never reuse old-policy cached passes.

Only after a positive uncensored confirmation with all hard checks passing:

1. Prepare the exact confirmed policy as a canonical default in an isolated
   source copy, keeping explicit original/candidate diagnostic modes available.
   Canonical dayplayer, walk helpers and stat_probe's default must agree.
   Do not change the confirmed selection body, automatic drills or game rules.
2. Verify the source-cache identity changes, and current counter/HP guard and
   original-mode tests remain meaningful under the new canonical choice.
3. Run the original16seed tuned-picked canonical row with its unchanged≥1.15
   threshold. A targeted canonical-row check is not the whole gate. Keep every
   seed and absolute-arrival/King/censoring tradeoff; no grants or slower PICKED.
4. Complete the declared relevant worker/recovery/upgrade regressions and
   default-policy validation before adoption. The existing library/WASM remain
   unchanged unless an actual engine change requires fresh evidence.

A rejected, censored or inconclusive confirmation does not authorize this
default change or a sample extension. Archive its exact result and choose a
different mechanism. The broader queue and independent fun acceptance stay open.
