## What happened (automated capture plus agent visual review; no owner or player feedback in this pass)

The capture script opens the Hub through `town.openHero` and taps each tab. It saves the viewport and,
for some views, a grown-viewport inventory. It also records window, hub and tab geometry, targets
under 44 px, and horizontal overflow (`before-metrics.json`, `after-metrics.json`).

- The tab scroll-into-view fix from Cut259 holds. At 402×681 with the progressed saves, the window is
  only 411 px tall. After a tap, the tabs scroll up and the section starts under them, so the content
  is visible. At 1440, the content is already visible and nothing scrolls. After this pass, the tabs
  stop 56 px below the window top, so the sticky close stud no longer covers the right-hand tab.
- No control was under 44×44 px in any view, before or after. No horizontal overflow was found.

## Interpretation and confidence

- High confidence on 1–3, 5–11: each is visible in the before/after pairs at both widths. The width and
  jump fixes are measured: the Hub is 282→330 px at 402, and the window is 940×786 on every tab at 1440.
- Medium-high confidence on 4a. The overlay colour matches the samples, `--mist` rgb(164,188,214)
  against a weakest background of rgb(164,187,213). The failing samples sat at the window edges. After
  the change, the full compact hero-hub run passes with unchanged thresholds.
- These are agent observations on headless SwiftShader. Revalidate them if the window chrome
  (sticky bands, stud) or the Hub layout changes.
