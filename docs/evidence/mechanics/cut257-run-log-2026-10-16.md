## Perf chore: the worst-death verdict leaves the absence

`docs/evidence/mechanics/perf-attribution-2026-10-16.md` (the attribution) shows
the single deep-camp death verdict is 0.8–1.6 s of engine time and 41–64 % of a
deep absence, and that the client's per-slice JSON is not the cost. Change:
`web/src/app.ts` no longer computes it; the merged report carries
`worst_death_id`, and `web/src/ui/report.ts`'s `deepest` tile computes the
verdict only when the player opens it (the same lazy pattern the per-run verdict
chips already use). Verified by:

  to the death screen) and `screens` PASS;
- the pre/post attribution probe (`scratchpad/perf-attribution/app3.mjs
  scratchpad/perf-attribution/deep13.json`), which shows the `death` engine call
  disappearing from the absence when the tile is not opened;
- `lazy-verdict-groups.log` vs `baseline-cut13-cut29.log`: `cut13` and `cut29` fail
  with the four identical assertions each **with and without** the change, so
  those failures are pre-existing (stale forge-kit / keep-sheet / exit-line / day-0
  expectations) and are handed to the UI owner rather than caused here.
