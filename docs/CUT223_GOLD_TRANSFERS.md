# Cut223 — show where Gold moves

Implementation contract for queue25; acceptance pending.

Current feedback sends a small fixed-size shower toward the header after a
positive balance change. Watched exits and old chest collection also have their
own animations. Spending has no equivalent destination, and separate feedback
can repeat the same credit. A loaded save can look like an earned transfer.

## Change

Use explicit successful engine transaction boundaries: purchases, construction,
real run settlement and actual away settlement. Read the before/after Gold total
and Rust ledger; never calculate loot settlement or prices in the client. Opening
a screen, selecting a hero, importing a save and rejected actions are silent.

Match the longest old-ledger suffix with the new-ledger prefix. Show appended
credits and debits only if their sum reconciles with the actual balance change.
When bounded history prevents a reliable match, show only the actual net change
with an unnamed endpoint rather than inventing a receipt. Matching includes
owner, time, amount, reason, count and lost carry. Equal balances can still have
real opposing transfers; identical reads cannot create particles.

Transfers begin or end at the visible Gold counter. Use an actual Forge, Savings,
Guild hire, purchased control, cave or report receipt when it is visible. For
offscreen endpoints, use a short local directional movement and retain the
canonical receipt text; do not point at an unrelated building. Resolve geometry
after paint and reject disconnected anchors. Navigation cancels old particles.

Particle count and diameter grow logarithmically with value, bounded at12
particles per transfer,48 total particles and one second of motion. Full/Low/Off
and reduced-motion settings apply. Decorative particles never receive pointer
events or accessibility focus, and never replace actual amounts or receipts.
Merge repeated identical reasons within one transaction instead of playing
hundreds of offline events. No gameplay, ledger, RNG or save writes occur.

## Acceptance

1. Actual paid Forge, worker, resident and Savings operations reconcile their
   displayed transfers to Rust Gold and receipts. Owned equipment reuse and
   insufficient-Gold refusal create none.
2. Actual Bank/Return/Death settlement and eight-hour absence animate only
   credited Gold, including secured/protected Gold; lost carry creates none.
3. Repeated read, refresh, hero selection, import and navigation create no
   duplicate credit. Test bounded ledger eviction and repeated same-time rows,
   including zero-net credit/debit transactions.
4. Real-WASM320/400/1440, normal/200% text, Full/Low/Off/reduced-motion journeys
   preserve exact saves and Gold. Verify visible endpoints, navigation cleanup,
   particle bounds and missing/disconnected-anchor fallback.
5. Post settled before/after frames and a short motion capture from actual
   operations. Record exact source/package identity and measured frame cost.

Cut219 pacing and Cut221 measurements remain independent. This contract does
not authorize new rewards, automatic purchases or replacement wish chores.
